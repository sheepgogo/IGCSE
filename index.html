第 1 章 · 从题目到代码：开发流程与结构图

伪代码不是凭空写出来的。拿到一道 15 分的题，先要读懂它要什么（分析）、拆成几个小任务（设计）， 然后才是逐行写。这一章讲的就是这条流水线，以及考纲 7.1 要求你认得的两样东西： 开发流程的六个阶段与结构图 structure diagram。

1.1 一个程序的六个阶段

PROGRAM DEVELOPMENT LIFE CYCLE

考纲把“做出一个能用的程序”拆成六个阶段。它们的顺序固定，但允许往回跳：测试发现问题就回到编码，编码发现设计有漏洞就回到设计。

阶段做什么产出物考试怎么考
分析
Analysis		读题，列出程序要接收什么、要输出什么、遵守哪些规则输入输出清单、需求列表“说出这个程序的输入与输出”
设计
Design		把大问题拆成小任务，画结构图，写伪代码或流程图结构图 + 算法“画结构图”“写伪代码”
编码
Coding		把伪代码翻译成真正的语言（VB / Python / Java）源程序Paper 2 只考伪代码，不考具体语言
测试
Testing		用正常、边界、无效数据各跑一遍，比对预期结果测试计划 + 实际结果“给出一组测试数据并说明期望结果”（第 22 章）
改进
Refinement		修 bug、补功能、优化界面或效率新版本“评价这个程序还可以怎么改”
维护
Maintenance		交付后长期修问题、跟着需求变化改更新版本 + 文档名词题：维护包含哪几类工作
最容易混的两个阶段 测试是“证明它有错”，改进是“把错改掉、把功能补上”。题干问“发现问题之后下一步做什么”， 答案通常是“改进（refine）代码”，而不是“重新分析”。

1.2 IPO 表：把题干拆成三列

INPUT · PROCESS · OUTPUT

分析阶段的产物可以只用一张三列表表达，叫 IPO 表。写伪代码之前先填它，能避免“写到最后发现少读了一个数据”。

列问自己木地板报价的例子
Input 输入程序要从外面拿哪些数据？各是什么类型？房间长 RoomLength、宽 RoomWidth（REAL）、每平米单价 PricePerSqM（REAL）
Process 处理要算什么、判断什么、存什么？Area ← RoomLength * RoomWidth；Cost ← Area * PricePerSqM；加 10% 损耗
Output 输出最后要给用户看什么？面积 Area、总价 Cost
两个高频错位 ① 把“计算总价”写进 Input 列——它不是从外面拿的，是算出来的；
② 漏掉 Output。终端用户在屏幕上看到的那一项，才是 Output。

1.3 结构图：只画“谁调用谁”

STRUCTURE DIAGRAM

结构图（也叫自顶向下图、层次图）把程序拆成一层层的模块：最上面是主程序，下面一行是它调用的子程序，再往下是子程序自己调用的子程序。

箭头从来不加：竖线本身就表示“上层调用下层”。图中 CalcCost 又调用了 CheckInput，所以它画在第四层。

结构图能表达

  • 程序分成几个模块
  • 谁调用谁（层次关系）
  • 每个模块负责哪一件事

结构图不能表达

  • 执行顺序（谁先谁后）
  • 判断与循环（没有菱形）
  • 具体语句与变量
把结构图画成流程图的，一律 0 分 结构图里没有菱形、没有箭头、没有 START / STOP。看到这三样中的任何一样，就说明画错了图种。 顺序和分支是流程图（第 24 章）的事。

1.4 为什么要拆：自顶向下与模块化

TOP-DOWN & MODULAR

自顶向下（top-down）的意思是：先写主程序，把还没想清楚的部分先当成一个“黑盒”调用，等主流程跑通了再逐个把黑盒填实。这样任何时候手上都只有 10 行左右的代码要想。

// 第一步：主程序只表达流程，细节先留空
CALL GetInput
CALL CalcCost
CALL ShowResult

// 第二步：逐个填实（第 17 章会讲参数的写法）
PROCEDURE CalcCost(Length : REAL, Width : REAL, Price : REAL)
   DECLARE Area : REAL
   Area ← Length * Width * 1.1   // 含 10% 损耗
   OUTPUT "Area = ", Area, " Cost = ", Area * Price
ENDPROCEDURE

模块化带来的四个好处，考试常作为 2 分简答题：

  • 好读：主程序只有五行，一眼看出整体结构。
  • 好测：每个子程序可以单独用几组数据测试，出错范围小。
  • 好复用：CheckInput 在别的程序里也能直接用。
  • 好分工：几个人可以同时写不同模块，只要接口（参数）约定好。
拆到多细算合适 一个模块只做一件事，名字能用“动词 + 名词”说清楚（CalcCost、GetInput）。 如果名字只能叫 Process 或 DoStuff，说明它干了不止一件事，还要再拆。

1.6 真题小练：图书借阅

PRACTICE
题目 某图书馆要写一个程序：输入借书天数 Days，前 7 天每天 0.5 元，超过 7 天的部分每天 1 元； 如果读者是会员（IsMember 为 TRUE），总费用打九折。输出 Fine。 要求：(a) 写出 IPO 表；(b) 画出结构图（3 个模块）；(c) 写出 CalcFine 的伪代码。

(a) IPO 表

列内容
InputDays（INTEGER）、IsMember（BOOLEAN）
Process判断是否超过 7 天 → 分段计价 → 会员再乘 0.9
OutputFine（REAL）

(b) 结构图：顶层 LibraryFine，第二层三个模块 —— GetInput（读天数与会员状态）、CalcFine（算钱）、ShowFine（输出）。不要再往下拆，因为每个模块都只做一件事。

(c) 伪代码

PROCEDURE CalcFine(Days : INTEGER, IsMember : BOOLEAN)
   DECLARE Fine : REAL
   IF Days <= 7 THEN
      Fine ← Days * 0.5
   ELSE
      Fine ← 7 * 0.5 + (Days - 7) * 1.0
   ENDIF
   IF IsMember = TRUE THEN
      Fine ← Fine * 0.9
   ENDIF
   OUTPUT "Fine = ", Fine
ENDPROCEDURE
得分点 ① 两个分支都要算（<= 7 与 > 7）；② 超期部分要减 7 再乘 1 元； ③ 会员折扣不写在分支里，而是单独一个 IF——写进 ELSE 里会漏掉“借 3 天的会员”。

第 2 章 · 变量与常量

程序要处理数据，就得先有地方放数据。变量（variable）是内存里的一个命名格子， 里面的值在程序运行中可以变；常量（constant）是同一个格子，但值一旦放进去就不许改。 这一章看起来最简单，却是后面所有题的第一句代码——写名字、写类型、写箭头，一个都不能错。

2.1 为什么要先 DECLARE

WHY DECLARE FIRST

伪代码不是自然语言，它是一种“接近代码的说明”。计算机执行前必须知道两件事：这块内存叫什么、它准备装什么类型的数据。所以每条声明语句都包含三段：

DECLARE   Total   :   INTEGER
   |        |     |      |
   |        |     |      +-- 数据类型：只装整数
   |        |     +--------- 冒号：伪代码里用 : 连接名字与类型
   |        +--------------- 变量名：自己起，要有意义
   +------------------------ 关键字：声明

三个变量就要写三行声明（课件里的标准写法是一行一个）。虽然也有考试允许 DECLARE A, B : INTEGER 这种合并写法，但分行写永远不得分更少，也最不容易漏。

2.2 赋值：箭头 ← 的方向感

ASSIGNMENT

赋值语句永远只有一种读法：先算右边，再把结果放进左边。

Total ← 0                  // 把 0 放进 Total
Total ← Total + 1          // 先算 Total+1，再放回 Total（自增）
Average ← Total / 5        // 右边算完是个实数，存进 Average
错误写法 Total + 1 ← Total
左边必须是一个变量名，不能是表达式。
错误写法 Total = Total + 1
= 在伪代码里是比较（等于），不是赋值。
记忆点 ← 是“倒进去”，= 是“问一句相不相等”。 写 IF 的时候用 =，写赋值的时候用 ←，两者绝不互换。

2.3 常数：给“不会变的值”起个名字

CONSTANTS

课件的 National Holiday Homework 里有一题：Seconds 保存每分钟的秒数（60），Minutes 保存一小时的分钟数（60）。这两个值是固定的，用常量更合适。

CONSTANT SecondsInMinute = 60
CONSTANT MinutesInHour = 60
DECLARE TotalSeconds : INTEGER

TotalSeconds ← 3 * MinutesInHour * SecondsInMinute   // 3 小时 = 10800 秒
对比项变量 Variable常量 Constant
值运行中可以反复改变声明后不允许再改
写法DECLARE X : INTEGERCONSTANT Pi = 3.14
何时用需要累加、计数、接收输入圆周率、税率、单价、上限值
好处灵活可读性高；改一处就全部生效；防止被误改
考试常问 “为什么用常量而不用变量？” 标准答法：这个值在程序运行中不会改变，用常量可以避免它被意外修改， 并且如果以后要改（比如税率变了）只需改声明处一行，不用在程序里到处找。

2.4 变量名的规矩

NAMING RULES
  • 有意义：TotalMark 比 X 好，阅卷老师一眼看懂你的意图。
  • 不能有空格：用 TotalMark 或 total_mark，不能写 Total Mark。
  • 不能以数字开头：Mark1 可以，1Mark 不行。
  • 不能是保留字：DECLARE、IF、ARRAY、STRING 这些不能当变量名。
  • 大小写敏感不必纠结：伪代码不是真实语言，只要同一个变量前后写法一致就行。

第 3 章 · 五种数据类型

选类型的唯一标准是：这个数据要拿来做什么。要做算术就选数值类型（Integer / Real）， 要存字符就选 Char / String，只有两种状态（真/假）就选 Boolean。 考试里“选错类型”是最容易被扣的 1 分，而判断方法其实只有三条。

3.1 五种类型对照

FIVE DATA TYPES
类型存什么例子怎么判断
INTEGER整数（无小数点）17、-3、1001要参与加减乘除、计数、比较大小，而且一定没有小数
REAL实数（可带小数）47.46、22.5、3.14可能出现小数：价格、身高、温度、平均分
CHAR单个字符'A'、'7'、'*'只需要一个字符，用单引号
STRING一串字符“Alice”、“02/10/2017”多个字符，或者虽然是数字但不做算术（电话、邮编、日期）
BOOLEAN真 / 假TRUE、FALSE只有两种可能的状态：是否找到、是否交换、是否有效
一条判断链 ① 只有真/假两种状态？→ BOOLEAN。
② 要拿来做算术吗？
    要 → 一定有小数吗？有 → REAL；没有 → INTEGER。
    不要 → 只有一个字符吗？是 → CHAR；不是 → STRING。

3.2 最容易错的三个坑

COMMON TRAPS

坑 1：电话号码 / 邮编

“020 7946 0018” 看起来全是数字，但它有前导 0、有空格、不参与加减——所以是 STRING。 如果存成 Integer，前导 0 会消失。

坑 2：日期

“02/10/2017” 含斜杠、不能直接算，用 STRING； 若题目改口说“存年、月、日三个数”，那才是三个 INTEGER。

坑 3：分数 / 平均分

单科成绩可能是 INTEGER，但“平均分”往往出现小数，应选 REAL。 拿不准时看题目有没有出现小数点。

CHAR 和 STRING 的边界 'A' 是 CHAR（单引号，长度 1）；“A” 也可以当只有一个字符的 STRING。 考试里如果题目说“存一个字母等级 A–F”，写 CHAR 更贴切；如果说“存学生姓名”，一定是 STRING。

第 4 章 · 运算、DIV / MOD 与输入输出

伪代码的运算符只有三组：算术（+ − * / DIV MOD）、比较（= <> < > <= >=）、逻辑（AND OR NOT）。 其中 DIV 和 MOD 是 IGCSE 的高频考点，几乎每份卷子都会用到，因为它们是“判断奇偶”、“拆数字”、“判断整除”的唯一工具。

4.2 DIV 与 MOD：把除法拆成两半

QUOTIENT AND REMAINDER

除法 17 / 5 = 3.4 有两个“整数世界”的答案：商是 3，余数是 2。

17 DIV 5 = 3      // 只要整数部分（向下取整，不是四舍五入）
17 MOD 5 = 2      // 余数，17 - 3*5 = 2

// 关系恒成立：
a = (a DIV b) * b + (a MOD b)
三种必须会的用途

1. 判断奇偶

n MOD 2 = 1 是奇数，n MOD 2 = 0 是偶数。第 10 周那道“打印 1,3,5,7,9”就是靠它。

2. 判断整除

n MOD 5 = 0 表示 n 能被 5 整除。做“每 5 个换行”、“每 10 个求一次平均”时用它。

3. 拆出各位数字

n MOD 10 拿个位，n DIV 10 去掉个位。反复做就能逐位处理。

试一试 · DIV / MOD 计算器
输入两个整数，点击“计算”查看商、余数与常见判断结果。
易错 DIV 不是四舍五入：17 DIV 5 是 3，不是 3.4，也不是 4。 如果题目要求“保留两位小数”，那是 / 之后再处理，不是 DIV。

4.3 随机数 RANDOM

RANDOM

5.4 复合条件的四个坑

FOUR TRAPS
坑 1：边界少一个等号

题干说“11 到 18 岁可以参加”，正确写法是闭区间：

IF Age >= 11 AND Age <= 18 THEN       // 对：11 和 18 都能进
IF Age > 11 AND Age < 18 THEN         // 错：把 11 岁和 18 岁挡在外面
坑 2：AND 与 OR 混用不写括号

“是会员或者消费满 200，并且没有欠款” —— 这句话的正确结构是 (会员 OR 满 200) AND 无欠款。若写成下面第二行，语义就变成了“会员，或者（满 200 且无欠款）”：

IF (IsMember = TRUE OR Total >= 200) AND Arrears = 0 THEN   // 对
IF IsMember = TRUE OR Total >= 200 AND Arrears = 0 THEN     // 错：AND 先算
坑 3：NOT 只管住紧邻的那一项

NOT A = B 有歧义，读的人可能理解成 (NOT A) = B。要表达“A 不等于 B”，两种稳的写法：

IF NOT (A = B) THEN      // 明确：整个比较取反
IF A <> B THEN           // 更推荐：直接用不等于
坑 4：字符串比较是逐字符的

"Ann" = "ann" 是 FALSE，大小写不同就不相等；"Ann" < "Bob" 是 TRUE（按字符编码逐位比）。 要不区分大小写，两边都先 UCASE：

IF UCASE(Name) = "ANN" THEN
   OUTPUT "Match"
ENDIF

5.5 短路求值与条件的书写顺序

SHORT CIRCUIT

很多语言在算 A AND B 时，如果 A 已经是 FALSE，就不再算 B，这叫短路求值。伪代码不保证这一点，所以不能靠顺序来避免错误，但把“范围判断”写在前面仍然是好习惯，读代码的人一看就懂：

// 危险：若 i 已超出数组边界，A[i] 会出错
IF A[i] = Target AND i <= 10 THEN

// 安全：先确认 i 在范围内，再访问数组
IF i <= 10 THEN
   IF A[i] = Target THEN
      ...
   ENDIF
ENDIF
为什么不用一个 AND 解决 只要语言不保证短路，A[i] = Target AND i <= 10 就可能先访问越界的 A[i]。 把范围判断拆成外层 IF，任何语言都安全，阅卷老师也更容易给分。

5.6 德摩根定律：把“不满足”翻译成人话

DE MORGAN

题干经常反着问：“下列条件不成立时……”。这时要用两条恒等式把 NOT 拆进去：

原式等价于口诀
NOT (A AND B)(NOT A) OR (NOT B)否掉“并且” → 变成“或者”
NOT (A OR B)(NOT A) AND (NOT B)否掉“或者” → 变成“并且”

把比较运算也代进去，>= 取反是 <，> 取反是 <=：

// 及格条件：分数 >= 40 且 出勤 >= 80
IF Mark >= 40 AND Attendance >= 80 THEN
   OUTPUT "Pass"
ENDIF

// 不及格（上面整体取反）：分数 < 40 或 出勤 < 80
IF Mark < 40 OR Attendance < 80 THEN
   OUTPUT "Fail"
ENDIF
自查办法 写完“取反版”，用一组数据代进去验：Mark = 50, Attendance = 70 应该判 Fail。 原式是 FALSE，取反版必须是 TRUE，两边对不上就说明有一步写反了。

PATTERNS

第 7 章 · 内置函数与类型转换

伪代码里有一批“现成的工具”可以直接拿来用：取整的 ROUND / INT、 取字符编码的 ASC / CHR、在数字与字符串之间来回转的 NUM_TO_STR / STR_TO_NUM。 它们本身不难，难的是知道什么时候该用——尤其是拼接输出和逐字符处理的时候。

7.1 先分清“函数”和“过程”

FUNCTION vs PROCEDURE

内置函数和你在第 17 章写的 FUNCTION 是同一类东西：给进去几个参数，吐回来一个值。所以它只能出现在表达式里，不能单独当一条语句：

Total ← Total + LENGTH(Name)        // 对：函数的值参加运算
OUTPUT ROUND(Average)                  // 对：函数的值被输出
ROUND(Average)                         // 错：算完就扔了，什么也没发生
LENGTH(Name) ← 10                   // 错：函数结果不能当变量赋值
一句话区分 有返回值 → 用在表达式里（LENGTH、ROUND）； 只做事不返回值 → 单独一行（CALL PrintLine、OUTPUT）。

7.2 取整三兄弟：ROUND / INT / DIV

ROUNDING

“把小数变成整数”有三种完全不同的做法，混用就是错答案：

写法规则例子什么时候用
ROUND(x)四舍五入到整数ROUND(2.5) = 3
ROUND(2.4) = 2		平均分、价格、成绩——要“最接近”的整数
INT(x)直接砍掉小数部分（向零截断）INT(2.9) = 2
INT(2.1) = 2		“够几个”“能买几个”——只能少不能多
x DIV y整除，只取商的整数部分7 DIV 2 = 3两个整数相除取商；操作数必须是 INTEGER
两个致命细节 ① DIV 只接受整数：7.5 DIV 2 不合法，要先用 INT 转换；
② INT 不是四舍五入：INT(2.9) 是 2，不是 3。想凑整用 ROUND，或者写 INT(x + 0.5)。

做两位小数（比如金额）时，常见写法是 ROUND(Price * 100) / 100：先放大取整，再除回去。

DECLARE Cost, Rounded : REAL
Cost ← 12.3456
Rounded ← ROUND(Cost * 100) / 100     // 1234.56 四舍五入成 1235，再除 100 → 12.35

7.3 ASC 与 CHR：字符和编码互换

ASC / CHR

计算机里每个字符都有一个编号（ASCII 码）。ASC 把字符变成编号，CHR 把编号变回字符：

ASC("A")     // 65
ASC("a")     // 97   （大写与小写差 32）
ASC("0")     // 48
ASC(" ")     // 32

CHR(65)      // "A"
CHR(97)      // "a"
CHR(48)      // "0"

三个必背用途：

  • 判断是不是字母：Code >= 65 AND Code <= 90 是大写字母
  • 大小写互转：大写 + 32 = 小写，CHR(ASC(C) + 32)
  • 数字字符变数值：ASC("7") - ASC("0") = 7
为什么不用 UCASE / LCASE 整串转换用 UCASE / LCASE 更简单；ASC / CHR 是用来在循环里处理单个字符的， 比如只把首字母改大写、或者判断某个字符是不是数字。

逐字符处理的标准骨架（配合 SUBSTRING 每次取一个字符）：

FOR i ← 1 TO LENGTH(Word)
   Ch ← SUBSTRING(Word, i, 1)
   IF ASC(Ch) >= 65 AND ASC(Ch) <= 90 THEN
      Upper ← Upper + 1
   ENDIF
NEXT i

7.4 数字 ↔ 字符串：拼接前的必做一步

TYPE CONVERSION

伪代码里 & 只负责“把字符串粘起来”，它不会自动把数字变成字符串。所以要输出“总分：88”时，必须显式转换：

函数作用例子
NUM_TO_STR(n)数字 → 字符串NUM_TO_STR(88) = "88"
STR_TO_NUM(s)字符串 → 数字STR_TO_NUM("88") = 88
 
DECLARE Total : INTEGER
Total ← 88

OUTPUT "Total: " & NUM_TO_STR(Total)     // 对 → Total: 88
OUTPUT "Total: " & Total                 // 错：类型不匹配，不能拿数字去拼字符串
最容易错的一道题 从文件或 INPUT 读进来的一律是字符串。想拿它做加法必须先 STR_TO_NUM： 
INPUT AgeText                 // 输入 "15"，此时它是字符串
Age ← STR_TO_NUM(AgeText)    // 变成数字 15
OUTPUT Age + 1                 // 16

// 如果不转换： "15" + 1 会报错，或者被拼成 "151"（取决于实现）

反过来，“取一个数字的各位数字”既可以靠算术，也可以先转成字符串再逐位取：

// 算术法：258 → 2、5、8
Hundreds ← 258 DIV 100
Tens ← (258 DIV 10) MOD 10
Ones ← 258 MOD 10

// 字符串法：位数不定时更好用
S ← NUM_TO_STR(258)
FOR i ← 1 TO LENGTH(S)
   Digit ← STR_TO_NUM(SUBSTRING(S, i, 1))
   OUTPUT Digit
NEXT i

第 8 章 · 选择结构：IF 与 CASE

选择结构解决“要不要做”和“做哪一个”的问题。两种写法：IF 用于条件判断（可嵌套）， CASE 用于“一个值对应多个固定选项”。它们都能表达同一件事，但考试要求的写法不同， 而且 ENDIF / ENDCASE 的配对是本章唯一的硬性语法要求。

8.1 IF 的三种形态

THREE FORMS

单分支：条件成立才做

IF Mark >= 50 THEN
   OUTPUT "Pass"
ENDIF

双分支：二选一

IF Mark >= 50 THEN
   OUTPUT "Pass"
ELSE
   OUTPUT "Fail"
ENDIF

多分支：链式 IF（注意每个 IF 都要有自己的 ENDIF）

IF Grade = "A" THEN
   OUTPUT "Excellent work, well done!"
ELSE
   IF Grade = "B" THEN
      OUTPUT "Good effort, keep it up."
   ELSE
      IF Grade = "C" THEN
         OUTPUT "Satisfactory, there is room for improvement."
      ELSE
         IF Grade = "D" THEN
            OUTPUT "More practice is needed."
         ELSE
            IF Grade = "E" THEN
               OUTPUT "Please work harder and seek extra help."
            ELSE
               OUTPUT "Invalid Grade"
            ENDIF
         ENDIF
      ENDIF
   ENDIF
ENDIF
配对规则 数一数：5 个 IF，就必须有 5 个 ENDIF。 漏一个就是语法错误，整题作废。写的时候先把 ENDIF 写好再填中间，比写完再检查省事得多。

收尾关键字ENDIFENDCASE

第 9 章 · 循环结构

三种循环，考的不是语法，而是“什么时候用哪一种”： 次数已知用 FOR，次数未知、可能一次都不做用 WHILE， 次数未知、但至少要做一次用 REPEAT。判断顺序错了，程序就会多跑一次或者一次都不跑。

9.1 三种循环的语法骨架

SYNTAX

FOR（计数控制）

FOR i ← 1 TO 10
   OUTPUT i
NEXT i

循环变量从 1 数到 10，共 10 次，每次自动 +1，用 NEXT 收尾。

WHILE（前置条件）

Counter ← 0
WHILE Counter < 10 DO
   OUTPUT "*"
   Counter ← Counter + 1
ENDWHILE

先判断再执行；条件一开始就假，则一次都不执行。

REPEAT（后置条件）

Counter ← 0
REPEAT
   OUTPUT "*"
   Counter ← Counter + 1
UNTIL Counter >= 10

先执行再判断；至少执行一次。条件是“直到成立才停”。

最关键的一句话 WHILE 的条件是“继续做”的条件，REPEAT UNTIL 的条件是“停下来”的条件。 同一个任务，两边的条件往往互为反面：WHILE X < 10 对应 UNTIL X >= 10。 把条件抄错，就是死循环或者逻辑错。

9.2 一张表决定用哪个

CHOOSING
循环判断时机最少执行典型场景
FOR按次数，自动计数0 次（若上界 < 下界）遍历数组、打印 1–100、固定次数重复
WHILE循环体之前判断0 次读文件直到结束、菜单直到选退出、输入校验（可能本来就合法）
REPEAT循环体之后判断1 次必须先读一次数据才能判断的输入校验、至少执行一遍的菜单
判断口诀 题目里出现“for each”、“100 次”、“从 1 到 n” → FOR；
出现“while”、“只要…就”、“可能没有” → WHILE；
出现“repeat”、“至少一次”、“先输入再检查” → REPEAT。

9.5 循环的三个死法

THREE WAYS TO HANG

忘记自增

WHILE Counter < 10 DO
   OUTPUT "*"
ENDWHILE        // 死循环

条件永远为真，循环永不结束。

UNTIL 条件写反

REPEAT
   ...
UNTIL Counter < 10   // 应为 >= 10

条件是“停止条件”，写反就一直做。

FOR 里再改循环变量

FOR i ← 1 TO 10
   i ← i + 1   // 不要这样
NEXT i

循环次数和你想的不一样，阅卷也扣分。

写循环的四步 ① 初始化（计数器/累加器清零）；② 写条件或次数；③ 写循环体；④ 更新计数器，并检查收尾关键字。 这四步在纸上按顺序写，几乎不会漏。

第 10 章 · 一维数组

要存 5 个温度，可以声明 5 个变量；要存 100 个温度，就不能这么干了。 一维数组（1D array / list）把“同类型的多个值”放进一个名字底下， 每个值用下标（index）区分。它真正带来的好处是：可以用一个循环处理全部元素。

10.1 定义里的五句话

DEFINITION

课件给的定义拆开看，每一句都是一个考点：

  1. 一维数组也叫 list（列表）。
  2. 它存储多个相同数据类型的元素——不能一半整数一半字符串。
  3. 所有元素共享同一个标识符（数组名），靠下标单独访问。
  4. 第一个下标可以是 0 也可以是 1，多数语言从 0 开始——但伪代码题要看题目怎么声明。
  5. 用途：存放需要查找和排序的一组数据，比如姓名、温度值。
为什么必须“同类型” 因为内存要按固定大小连续分配。ARRAY[0:9] OF INTEGER 就是“连续 10 个整数格子”。 要同时存姓名（字符串）和分数（整数），靠的是两个数组 + 同一下标，也就是第 13 章的平行数组。

10.2 声明的四个要素

DECLARATION
DECLARE MyList : ARRAY[0:9] OF INTEGER
            |        |      |       |
            |        |      |       +-- 元素类型
            |        |      +---------- 下标范围：首 0，尾 9（共 10 个）
            |        +----------------- 关键字 ARRAY
            +-------------------------- 数组名

要素对照

数组名MyList
首下标0
末下标9
元素个数10（9 − 0 + 1）
数据类型INTEGER

常见声明写法

DECLARE Marks : ARRAY[0:4] OF INTEGER     // 5 个整数
DECLARE Temp : ARRAY[0:4] OF REAL         // 5 个实数
DECLARE Name : ARRAY[1:5] OF STRING       // 5 个字符串
DECLARE Grid : ARRAY[1:3,1:4] OF INTEGER  // 二维：3 行 4 列
下标起点要看题目 课件里两种写法都出现过：ARRAY[0:4]（Temperatures、Initials、MyList）和 ARRAY[1:5]（Week 13 的 Name、StudentNo）。没有“统一标准”，只有“按声明来”： 声明写 [1:5] 就用 1–5，写 [0:4] 就用 0–4。 贸然从 0 开始遍历一个 [1:5] 的数组，会读到一个不存在的元素。

11.5 平均值 Average

平均值 = 总和 ÷ 元素个数。它是求和的“延伸”：先照抄求和，最后加一行除法。

MyList[1] ← 27
MyList[2] ← 5
MyList[3] ← 39
MyList[4] ← 18

   Total ← Total + MyList[index]

OUTPUT "Total value is ", Total

04     IF List[Counter] > Max THEN
05        Max ← List[Counter]
06     ENDIF
07     IF List[Counter] < Min THEN
08        Min ← List[Counter]
09     ENDIF
10  NEXT Counter
11  OUTPUT "Maximum value is ", Max
12  OUTPUT "Minimum value is ", Min
错误问题改正
1第 04 行比较方向反了：找最大值却用了 <改为 IF List[Counter] > Max THEN
2第 07 行变量名拼错：Count 不是 Counter改为 IF List[Counter] < Min THEN
3第 10 行收尾关键字错：FOR 循环要用 NEXT改为 NEXT Counter
这类题的三步扫描法 ① 看比较方向（找最大用 >，找最小用 <）； ② 看变量名（Counter / Count / Counter 混用是经典陷阱）； ③ 看收尾关键字与循环类型是否匹配（FOR→NEXT，WHILE→ENDWHILE，IF→ENDIF，CASE→ENDCASE）。 三步扫完，绝大多数错误都能抓到。
还有一个标准算法 考纲里和“求和 / 计数 / 极值 / 平均”并列的还有线性查找——在数组里找某个值在第几个。 它的骨架多了一个标志变量和一个位置变量，见第 15 章。

第 12 章 · 算法模式库：八个万能骨架

EIGHT PATTERNS
模式一：累加求和

12.5 真题小练：单词统计

PRACTICE
题目 输入一个单词 Word（只含小写字母）。要求：(a) 统计其中元音字母个数； (b) 判断是否所有字符都相同（例如 "aaaa"）；(c) 输出反转后的单词。 
DECLARE Word, Rev, Ch, First : STRING
DECLARE i, Vowels : INTEGER
DECLARE Same : BOOLEAN

INPUT Word
Vowels ← 0
Rev ← ""
Same ← TRUE
First ← SUBSTRING(Word, 1, 1)

FOR i ← 1 TO LENGTH(Word)
   Ch ← SUBSTRING(Word, i, 1)

   IF Ch = "a" OR Ch = "e" OR Ch = "i" OR Ch = "o" OR Ch = "u" THEN
      Vowels ← Vowels + 1
   ENDIF

   IF Ch <> First THEN
      Same ← FALSE
   ENDIF

   Rev ← Ch & Rev            // 每读一个字符就放到前面
NEXT i

OUTPUT "Vowels: ", Vowels

   OUTPUT "All characters are the same"
ELSE
   OUTPUT "Characters differ"
ENDIF
OUTPUT "Reversed: ", Rev
三处最值钱的细节 ① 三个结果共用一个循环；② 反转靠 Rev ← Ch & Rev（新字符放前面），不是 Rev & Ch； ③ Same 初始为 TRUE，只要有一个不同就置 FALSE——这是“全体满足”型标志，方向和 Found 相反。

13.3 真正的考点：排序时必须同步移动

THE REAL TRAP

如果只对 StudentMark 排序，排完之后分数从小到大，但姓名还停在原位——姓名和分数就对不上了。 所以交换的时候，三个数组的同一对下标必须一起换。

// 按分数从低到高排序，同时移动姓名和学号
DECLARE TempMark : INTEGER
DECLARE TempName : STRING
DECLARE TempNo : INTEGER
DECLARE i : INTEGER
DECLARE Last : INTEGER
DECLARE Swap : BOOLEAN

Last ← 5
REPEAT
   Swap ← FALSE
   FOR i ← 1 TO Last - 1
      IF StudentMark[i] > StudentMark[i + 1] THEN
         // 交换分数
         TempMark ← StudentMark[i]
         StudentMark[i] ← StudentMark[i + 1]
         StudentMark[i + 1] ← TempMark
         // 交换姓名（同样三步）
         TempName ← Name[i]
         Name[i] ← Name[i + 1]
         Name[i + 1] ← TempName
         // 交换学号
         TempNo ← StudentNo[i]
         StudentNo[i] ← StudentNo[i + 1]
         StudentNo[i + 1] ← TempNo
         Swap ← TRUE
      ENDIF
   NEXT i
   Last ← Last - 1
UNTIL (NOT Swap) OR Last = 1
最高频失分 只交换了 StudentMark，忘了交换 Name。 题目一旦说“显示按分数排序后的姓名列表”，只排一个数组就是错的——数据关联被破坏，一分不给。

第 14 章 · 冒泡排序 Bubble Sort

冒泡排序的思想只有一句：反复比较相邻的两个元素，逆序就交换。 每走完一趟，最大的那个元素一定被“推”到了末尾——像气泡浮到水面，所以叫冒泡。 难点不在理解，而在三重控制：趟数、边界收缩、提前结束标志。

14.1 定义（课件原文 + 逐句翻译）

DEFINITION

“Bubble sort is a sorting algorithm. It compares adjacent elements. If they are in the wrong order, they are swapped. We repeat passes through the list. Each pass moves the largest unsorted item to its correct position at the end of the list. We stop when a pass makes no swaps or only one element remains.”

原文含义
compares adjacent elements只比较相邻的两个元素（下标 i 和 i+1），不跳着比
if wrong order, swapped升序排序时，“前大后小”就是逆序，要交换
repeat passes一趟不够，要反复走多趟
each pass moves the largest to the end每趟结束，未排序部分的最大值一定落在末尾
stop when no swaps, or one element remains两个终止条件：整趟没有交换（已有序），或只剩 1 个元素

14.2 完整伪代码

THE ALGORITHM
First ← 1
Last ← 10
REPEAT
   Swap ← FALSE
   FOR Index ← First TO Last - 1
      IF Temperature[Index] > Temperature[Index + 1]
      THEN
         Temp ← Temperature[Index]
         Temperature[Index] ← Temperature[Index + 1]
         Temperature[Index + 1] ← Temp
         Swap ← TRUE
      ENDIF
   NEXT Index
   Last ← Last - 1
UNTIL (NOT Swap) OR Last = 1
行代码为什么这么写
1–2First ← 1 / Last ← 10标记“未排序区间”的左右边界。数组有 10 个元素
3REPEAT趟数事先不知道，用后置循环
4Swap ← FALSE每趟开始时清零，用来记录这一趟有没有交换过
5FOR Index ← First TO Last - 1内层只走到 Last − 1，因为要访问 Index + 1，否则越界
6IF A[Index] > A[Index+1]升序排序：前一个更大就说明顺序错了
7–9三步交换（借 Temp）不能直接 A[i] ← A[i+1]，否则原值被覆盖
10Swap ← TRUE只要交换过一次，就说明还没排好
12Last ← Last - 1本趟的最大值已就位，右边界收缩一格，下一趟少比一次
13UNTIL (NOT Swap) OR Last = 1整趟无交换 → 有序；或只剩 1 个元素 → 无需再排
为什么需要 Temp（课件旁注在问的就是这个） 交换两个变量不能直接互相赋值。A ← B 会把 A 原来的值抹掉，接着 B ← A 拿到的已经是新值了。 所以要先把这个值暂存到 Temp： 
Temp ← A[i]        // 先把 A[i] 备份（否则会丢）
A[i] ← A[i+1]      // 用后者覆盖前者
A[i+1] ← Temp      // 再把备份放到后面

14.4 趟数与比较次数

COMPLEXITY

n 个元素：

  • 最多需要 n − 1 趟（每趟至少确定一个元素的位置）。
  • 第 1 趟比较 n − 1 次，第 2 趟 n − 2 次……第 k 趟比较 n − k 次。
  • 最坏情况总比较次数 = (n−1) + (n−2) + … + 1 = n(n−1)/2。
  • 最好情况（数组本来就排好）：只跑 1 趟，比较 n − 1 次，因为没有发生交换，Swap 保持 FALSE，循环立刻结束。
这解释了 Swap 标志的价值 没有 Swap 标志，即使数组已经有序也要硬跑满 n−1 趟。 加了它，程序能“察觉”自己已经排好，提前退出——这是效率优化的典型手段，也是考试常问的“为什么用布尔标志”。

14.5 五个经典错误

FIVE BUGS
错误后果
FOR Index ← First TO Last越界：访问了 Index + 1，数组尾部不存在
Swap ← FALSE 写在 FOR 里面每轮都被清零，永远不知道整趟是否交换过，可能提前结束
忘记 Last ← Last - 1边界不收缩，虽然能排好但白跑很多次，效率低
不用 Temp 直接交换一个值被覆盖丢失，数组出现重复值
UNTIL Swap条件写反：应在“没交换”时停，写反会变成交换了就停
升序还是降序 只改一个符号：IF A[Index] > A[Index+1] 是升序（逆序才换）； 改成 < 就是降序。考试若要求“从高到低”，别忘记改这一处。

第 15 章 · 线性查找 Linear Search

找东西最笨也最可靠的办法：从第一个开始，一个一个比下去。这就是线性查找（也叫顺序查找）。 它和冒泡排序一起，是 0478 考纲明确要求的两个“标准算法”。 更值得记的是它的骨架——循环 + 一个 BOOLEAN 标志 + 一个位置变量， 这套骨架能改写出查重、登录验证、库存查询几乎所有“找”的题。

15.1 算法在做什么

THE IDEA

给定一个数组和一个目标值，从头到尾逐个比较，只有三种结局：

  • 找到：某个元素等于目标 → 记下它的下标，停止。
  • 没找到：全部比完，没有一个相等 → 输出“不存在”。
  • 提前知道不在：如果数组已按升序排好，一旦遇到比目标更大的元素，后面不可能再有目标，可以立刻停。
它和第 21 章的“存在检查”是同一个算法 第 21 章那段 Found 校验就是线性查找的简化版：只回答“在不在”。 本章多了一个位置变量 Position，回答“在第几个”。
比较项线性查找说明
数据是否要预先排序不要求这是它最大的优点：乱序名单、随时新增的记录都能直接查
最多比较几次n 次目标在最后一个，或者根本不存在
最少比较几次1 次目标正好是第一个元素
平均比较几次(n + 1) / 2目标平均落在中间位置
n 很大时慢n = 10000 时最坏要比一万次；有序数据改用二分查找（第 16 章），只需约 14 次

15.6 有序数组的提前结束

SORTED CASE

如果数组已按升序排好，比较时一旦发现 Names[i] > Target，就可以立刻停：后面只会更大，不可能相等。

WHILE i <= 8 AND Found = FALSE AND Names[i] <= Target
   IF Names[i] = Target THEN
      Found ← TRUE
      Position ← i
   ENDIF
   i ← i + 1
ENDWHILE
代价与取舍 这招只在“数组已经有序”时成立。如果为了查一次先排一次序，排序的成本（冒泡是 n² 量级）远大于省下的几次比较，得不偿失。 所以现实里的选择是：数据基本不变、要查很多次 → 先排序再查；数据乱、只查一两次 → 直接线性查找。

这条思路就是第 16 章二分查找的起点：有序 + 每次砍掉一半，比较次数从 n 降到 log₂n。

第 16 章 · 二分查找 Binary Search

线性查找一次只能排除一个元素，二分查找一次排除一半。代价是数据必须先排好序。 它不在 0478 的必考范围内，但几乎所有“比较两种查找算法”“为什么大数据要用二分”的题都要用到它， 而且它是把 WHILE + 两个指针 + 一个标志组合起来的绝佳练习。

16.1 前提与直觉

THE IDEA

查纸质词典找一个词，你不会从第一页翻起——你会翻到中间，看目标在前面还是后面，然后把另一半直接合上。 二分查找就是这个动作：

  • 前提 1：数据已按顺序排好（升序或降序，全篇统一）。没排序就不能用。
  • 前提 2：能随机访问中间元素。数组可以（A[Mid] 一步到位），链表不行。
  • 做法：用 Low 和 High 圈住“还有可能”的区间，每次看中间那个，扔掉一半。
三个变量各管什么 Low 是区间左端，High 是右端，Mid 是每次算出来的中点。 区间用闭区间：Low 和 High 指的位置本身还有可能是答案，所以循环条件是 Low <= High。

16.4 比较次数：为什么它这么快

EFFICIENCY

每比较一次，候选区间就少一半：n → n/2 → n/4 → … → 1。所以最多比较 log₂(n) 向上取整再加 1 次， 常用记法是：n 个元素最多 ⌈log₂(n + 1)⌉ 次。

元素个数 n线性查找最坏二分查找最坏差距
1515 次4 次快 3.75 倍
1 0001 000 次10 次快 100 倍
100 万1 000 000 次20 次快 5 万倍
为什么 15 个元素是 4 次 2⁴ = 16 ≥ 15，四次减半就能把区间缩到 1 个。反过来，10 个元素也是 4 次（2³ = 8 < 10）， 所以“元素翻倍，次数只多 1”——这就是对数增长。
别漏掉排序的成本 二分要求有序。如果数据本来是乱的，先排序（冒泡 O(n²)）再二分，只查一次时反而比线性查找慢。 二分的优势场景是：数据已经有序，或者要反复查很多次。

第 17 章 · 子程序：过程与函数

当同一段代码要写第二遍的时候，就该把它抽成一个子程序（subroutine）。 PROCEDURE 负责“做一件事”（不带回值），FUNCTION 负责“算出一个值”（必须 RETURN）。 这一章还有 IGCSE 的经典考点：参数到底是复制一份（BYVALUE）还是把原变量交出去（BYREF）。

17.1 为什么要拆出子程序

WHY SUBROUTINES

想象主程序里有两个地方都要“输出菜单”。不拆的话，同样的 OUTPUT 要抄两遍；改一个字就得改两处，漏一处就出 bug。拆成子程序后：

  • 不重复：一份代码，随处调用，改动只发生在定义处。
  • 主程序变短、变好读：阅卷人和你自己都能一眼看出“程序分几步”。
  • 错误好定位：出问题时只需要检查那一个子程序。
术语含义
子程序 subroutine一段有名字、可反复调用的代码块的统称，包含 PROCEDURE 和 FUNCTION 两种
定义 definition写出子程序的完整代码（只定义不会执行）
调用 call在主程序（或其他子程序）里执行它
参数 parameter调用时传给子程序的数据；定义里写的是“形参”，调用时给的是“实参”

17.2 PROCEDURE：做一件事，不带回值

PROCEDURE
PROCEDURE ShowMenu()
  OUTPUT "1. Add a student"
  OUTPUT "2. Show class average"
ENDPROCEDURE

// 主程序里调用（必须有 CALL）：
CALL ShowMenu()

带参数的版本——参数写在括号里，每个参数都要单独标注类型：

PROCEDURE ShowMark(Name : STRING, Mark : INTEGER)
  OUTPUT Name, " scored ", Mark
ENDPROCEDURE

// 调用时按顺序给出实参：
CALL ShowMark("Alice", 87)
错误 ShowMark("Alice", 87)
调用 PROCEDURE 必须写 CALL。漏写 CALL 是最低级的丢分。
错误 PROCEDURE ShowMark(Name, Mark)
形参不能只有名字没有类型，每个参数都要 : 类型。

17.3 FUNCTION：算出一个值，必须 RETURN

FUNCTION

FUNCTION 和 PROCEDURE 有两处不同：声明里要多写一句 RETURNS 类型，函数体里必须有一句 RETURN 把值送回去。

FUNCTION GetMax(List : ARRAY[1:5] OF INTEGER) RETURNS INTEGER
  DECLARE i : INTEGER
  DECLARE Max : INTEGER
  Max ← List[1]
  FOR i ← 2 TO 5
    IF List[i] > Max THEN Max ← List[i]
  NEXT i
  RETURN Max
ENDFUNCTION

// 调用：直接用在表达式里，不写 CALL！
DECLARE Highest : INTEGER
Highest ← GetMax(Scores)
OUTPUT "Highest mark is ", Highest

作用执行一段操作（输出、写文件、排序……）计算并返回一个值
返回值没有必须有 RETURN 值
声明尾部ENDPROCEDURE多一句 RETURNS 类型，以 ENDFUNCTION 收尾
调用写法CALL ShowMenu()X ← GetMax(Scores)，出现在表达式里
典型用途菜单、校验重输、写文件求最大值、算平均、查校验结果
记忆点 一句话区分：PROCEDURE 是“去做”，FUNCTION 是“去算”。算出来的结果要有人接住 （用 ← 存进变量），所以 FUNCTION 绝不用 CALL。

17.4 参数传递：BYVALUE 与 BYREF

PARAMETER PASSING

这是 Paper 2 的经典考点。同一个子程序，参数传递方式不同，结果完全不同：

方式写法效果
值传递 BYVALUE(A : INTEGER) 或 (BYVALUE A : INTEGER)传进去的是副本；子程序里怎么改，主程序的原值都不受影响
引用传递 BYREF(BYREF A : INTEGER)传进去的是变量本身；子程序里一改，主程序的原值真的变了

什么时候用 BYREF？——当你需要子程序带回不止一个结果的时候。经典例子是交换两个变量：

PROCEDURE Swap(BYREF A : INTEGER, BYREF B : INTEGER)
  DECLARE T : INTEGER
  T ← A
  A ← B
  B ← T
ENDPROCEDURE

// 主程序：
DECLARE X : INTEGER
DECLARE Y : INTEGER
X ← 10
Y ← 20
CALL Swap(X, Y)
// 现在 X = 20, Y = 10（只有 BYREF 才能做到）
试一试 · 同一个 Swap，两种传参方式的差别
分别点击两个按钮，观察 A ← B 这一步在两种方式下各自改了谁。
写法细节 BYREF / BYVALUE 写在参数名之前、类型之前：(BYREF A : INTEGER)。 不写的时候默认 BYVALUE；数组作参数时习惯写 BYREF（复制整个数组太浪费）。

17.5 局部变量与全局变量

LOCAL AND GLOBAL

在子程序内部 DECLARE 的变量是局部变量：它只在子程序运行期间存在，主程序看不见它。Swap 里的 T 就是一个典型的局部变量——它只是借来倒一下手。

  • 局部优先：考试写子程序时，用到的临时变量一律在子程序里 DECLARE。这能保证子程序不“偷偷”改坏主程序的数据。
  • 同名不冲突：子程序里的局部变量和主程序变量同名时，各是各的，互不影响。
  • 数据进来靠参数，结果出去靠 RETURN / BYREF：这是子程序与外界交换信息的两条正规通道，别走“全局变量”的捷径。

1FUNCTION 里忘了 RETURN。评分标准里 RETURN 是单独的 1 分。

3调用 PROCEDURE 漏写 CALL。

第 18 章 · 二维数组：把一排格子变成一张表

一维数组是一排格子，二维数组是一张行 × 列的表格。成绩表（30 行 × 5 列）、 棋盘、座位表——只要数据有“行”和“列”两个方向，就该用二维数组。它只是把一维数组的 “一个下标”换成“两个下标”，遍历方式从一层循环换成两层循环。

18.1 声明：先写行，再写列

DECLARATION
DECLARE Grid : ARRAY[1:3, 1:4] OF INTEGER
//               |    |   |    |
//               行范围   列范围
  • 第一个下标范围是行（1 到 3），第二个是列（1 到 4），中间用逗号隔开。
  • 元素个数 = 行数 × 列数 = 3 × 4 = 12 个。
  • 和一维数组一样，上下界由声明决定，访问越界就是运行时错误。
与一维对照 一维 ARRAY[0:9] 只有“格子编号”；二维 ARRAY[1:3, 1:4] 的每个格子有 坐标（行号, 列号）。记住“先行后列”这个固定顺序，考试写反会连带错遍历方向。

18.2 访问：Grid[行, 列]

18.3 双层循环：外层定行，内层定列

TRAVERSAL

遍历整张表需要两层 FOR。外层循环变量做行号，内层做列号，就是最常见的“按行扫一遍”：

// 按行遍历：1-1  1-2  1-3  1-4  2-1  2-2 …
FOR Row ← 1 TO 3
  FOR Col ← 1 TO 4
    OUTPUT Grid[Row, Col]
  NEXT Col
NEXT Row

把两个变量换一下位置，就变成“按列扫”——每一轮输出一整列：

// 按列遍历：1-1  2-1  3-1  1-2  2-2 …
FOR Col ← 1 TO 4
  FOR Row ← 1 TO 3
    OUTPUT Grid[Row, Col]
  NEXT Row
NEXT Col
错误 两个 NEXT 顺序写反：NEXT Row 出现在 NEXT Col 前面。
内层循环必须先收口。谁在后声明、谁最后 NEXT。
错误 两层 FOR 用了同一个循环变量名。
内外层变量必须不同（如 Row 与 Col），否则外层计数被内层破坏。

18.4 三个常考算法

TYPICAL TASKS

1. 全表求和

Total ← 0
FOR Row ← 1 TO 3
  FOR Col ← 1 TO 4
    Total ← Total + Grid[Row, Col]
  NEXT Col
NEXT Row

2. 每行求和

FOR Row ← 1 TO 3
  RowTotal ← 0        // 每行开始先清零！
  FOR Col ← 1 TO 4
    RowTotal ← RowTotal + Grid[Row, Col]
  NEXT Col
  OUTPUT "Row ", Row, " total: ", RowTotal
NEXT Row

3. 找某个值的位置

FoundRow ← 0
FOR Row ← 1 TO 3
  FOR Col ← 1 TO 4
    IF Grid[Row, Col] = Target THEN
      FoundRow ← Row
      FoundCol ← Col
    ENDIF
  NEXT Col
NEXT Row
注意区别 “全表求和”的累加器在两层循环之外初始化；“每行求和”的累加器在外层循环之内、内层之外初始化。 放错位置的后果：全表求和变成只有最后一行的值，或行合计越加越大。

18.5 真题小练：成绩表

EXERCISE
题目 一个班级有 20 名学生，每名学生有 3 次测验成绩。声明一个二维数组存放全部成绩， 并输出每名学生的三次成绩之和。 
DECLARE Marks : ARRAY[1:20, 1:3] OF INTEGER
DECLARE Row : INTEGER
DECLARE Col : INTEGER
DECLARE RowTotal : INTEGER

// 读入（示意）
FOR Row ← 1 TO 20
  FOR Col ← 1 TO 3
    OUTPUT "Enter mark for student ", Row, ", test ", Col
    INPUT Marks[Row, Col]
  NEXT Col
NEXT Row

// 每行求和并输出
FOR Row ← 1 TO 20
  RowTotal ← 0
  FOR Col ← 1 TO 3

阅卷得分点 声明 1 分（行、列范围齐全），读入循环 1 分（INPUT 在内层），求和与输出各 1 分。 RowTotal ← 0 的位置单独算分——放在两层循环之外直接丢掉这 1 分。

第 19 章 · 记录类型：把一个对象的信息装进一个格子

平行数组的痛点是“数据越多，数组越多，排序越容易错位”。 记录（Record）用 TYPE 定义一种新的组合类型，把 姓名、学号、分数打包成一个变量。第 13 章那三个平行数组，用记录以后只剩一个。

19.1 从平行数组的痛点说起

WHY RECORDS

90 名学生，每人有姓名、学号、分数。平行数组的方案：

DECLARE Name      : ARRAY[1:90] OF STRING
DECLARE StudentNo : ARRAY[1:90] OF INTEGER
DECLARE Mark      : ARRAY[1:90] OF INTEGER

三个数组靠同一下标勉强关联。问题在第 14 章已经见过：排序时三个数组必须同步交换，少动一个就全错位。

对比项平行数组记录数组
一个学生占几个数组每个属性各一个数组（N 个）一个类型打包，始终只有一个数组
关联方式靠“下标相同”的人为约定靠点号 Class[i].Mark，天然绑定
排序时交换N 个数组逐个交换，漏一个就错位整条记录一次交换，不可能拆散
可读性要靠注释说明对应关系字段名直接说明含义

19.2 定义类型：TYPE … ENDTYPE

TYPE DEFINITION

第一步是定义类型——不是声明变量，而是告诉计算机“我要一种新格子，里面有这几个分格”：

TYPE Student
  DECLARE Name  : STRING
  DECLARE No    : INTEGER
  DECLARE Mark  : INTEGER
ENDTYPE

// 第二步：用这个类型声明变量
DECLARE S1 : Student

// 第三步：用点号访问每个字段
S1.Name ← "Alice"
S1.No   ← 1024
S1.Mark ← 87
OUTPUT S1.Name, " scored ", S1.Mark
  • TYPE 与 ENDTYPE 成对出现，中间一行一个字段，字段也要写类型。
  • TYPE 定义只是“图纸”，定义完必须再 DECLARE 变量 : 类型 才有真正的存储空间。
  • 访问字段用变量名.字段名：S1.Mark。点号读作“的”——“S1 的 Mark”。
易错 S1 ← 87 是错的——记录不能整体赋一个数，只能逐字段赋值； 输出也一样，OUTPUT S1 不成立，要 OUTPUT S1.Name, S1.Mark。

19.3 记录数组：排序只需一次交换

ARRAY OF RECORDS

把记录类型当成数组元素的类型，就得到记录数组——90 个学生从三个数组变成一个：

DECLARE Class : ARRAY[1:90] OF Student

// 访问第 5 名学生的分数：
OUTPUT Class[5].Mark

// 读入全部学生：
DECLARE i : INTEGER
FOR i ← 1 TO 90
  OUTPUT "Enter name"
  INPUT Class[i].Name
  OUTPUT "Enter student number"
  INPUT Class[i].No
  OUTPUT "Enter mark"
  INPUT Class[i].Mark
NEXT i

排序时交换的威力在这里：一条临时记录就能搬走一个学生的全部信息：

DECLARE Temp : Student
// 冒泡排序比较处（按分数升序）：
IF Class[j].Mark > Class[j + 1].Mark THEN
  Temp         ← Class[j]
  Class[j]     ← Class[j + 1]
  Class[j + 1] ← Temp
ENDIF
对照第 13 章 平行数组排序要写 3 组临时变量（TempName、TempNo、TempMark），每组 3 行，共 9 行； 记录数组只要 3 行，而且不可能忘掉某个字段。这就是“打包”的价值。

19.4 记录的四个高频扣分点

COMMON MISTAKES
1TYPE 里漏了字段类型：Name : STRING 写成 Name。
2只用 TYPE 不 DECLARE 变量，直接开始用——图纸没有变成房子。
3点号用错对象：Student.Mark（类型名不是变量名），应为 S1.Mark 或 Class[i].Mark。
4整体赋值/整体输出：记录必须逐字段处理。

19.5 真题小练：定义与访问

EXERCISE
题目 一本藏书目录记录每本书的书名（BookTitle）、作者（Author）、馆藏编号（CatalogueNo）。 用记录类型定义并声明一个存放 500 本书的数组，写出给第 10 本书三个字段赋值的语句。 
TYPE Book
  DECLARE BookTitle  : STRING
  DECLARE Author     : STRING
  DECLARE CatalogueNo : INTEGER
ENDTYPE

DECLARE Library : ARRAY[1:500] OF Book

Library[10].BookTitle  ← "Computer Science Basics"
Library[10].Author     ← "A. Author"
Library[10].CatalogueNo ← 74213
评分习惯 这类题通常是 3–4 分：TYPE/ENDTYPE 各算一处，字段与类型算一处，DECLARE 数组算一处， 点号访问算一处。字段名照题目给的写，别自作主张改名。

第 20 章 · 文件操作：让数据活过一次运行

变量和数组都住在内存里，程序一结束就消失。要把数据长期保存，就要写进文件。 考纲只要求五条语句和一个固定循环：OPENFILE → READFILE / WRITEFILE → CLOSEFILE， 读文件永远配 EOF 循环。格式固定，背下来就是送分题。

20.1 五条语句与三种模式

SYNTAX OVERVIEW
语句作用
OPENFILE "Marks.txt" FOR 模式打开文件，声明接下来要怎么用它
READFILE "Marks.txt", 变量从文件读出一个值存进变量
WRITEFILE "Marks.txt", 值1, 值2把数据写进文件
CLOSEFILE "Marks.txt"关闭文件，必须与 OPENFILE 配对
EOF("Marks.txt")判断是否读到文件末尾（End Of File），真/假
模式打开后的效果典型用途
READ从头开始读，只读不写读取已有数据做统计
WRITE从头开始写，原有内容被清空新建文件、整体重写
APPEND写到末尾，原有内容保留日志、追加新记录
最危险的一行 OPENFILE "Log.txt" FOR WRITE 一执行，旧文件内容立即清空。 想保留旧数据追加新数据，必须用 APPEND。这是选择题最爱考的一个字。

20.2 写文件模板

WRITING
DECLARE Name : STRING
DECLARE Mark : INTEGER

OUTPUT "Enter name"
INPUT Name
OUTPUT "Enter mark"
INPUT Mark

OPENFILE "Marks.txt" FOR WRITE
WRITEFILE "Marks.txt", Name, Mark
CLOSEFILE "Marks.txt"

要点只有两个：文件名前后出现的位置必须完全一致（同一个字符串）；用完一定 CLOSEFILE。

为什么必须 CLOSE 数据先写进缓冲区，CLOSEFILE 才保证真正落盘；同时关闭后别的程序才能打开它。 阅卷标准里 CLOSEFILE 通常单独占 1 分，漏写就是漏分。

20.3 读文件模板：EOF 循环（最高频）

READING WITH EOF

读文件时你不知道里面有多少条数据，所以用 WHILE + EOF——“只要还没到文件末尾，就继续读”：

DECLARE ThisName : STRING
DECLARE ThisMark : INTEGER

OPENFILE "Marks.txt" FOR READ
WHILE NOT EOF("Marks.txt") DO
  READFILE "Marks.txt", ThisName
  READFILE "Marks.txt", ThisMark
  OUTPUT ThisName, " ", ThisMark
ENDWHILE
CLOSEFILE "Marks.txt"
  • NOT 不能少：EOF 为真表示“读完了”，所以循环条件是“NOT 读完了”。
  • READFILE 一次读一个值：写入时写了两个值（姓名、分数），读的时候也要读两次，顺序还要一样。
  • 循环体末尾的 READFILE 是“推进器”：没有它会永远读到同一条数据，死循环。
试一试 · 文件 Marks.txt 里存着 4 条记录，单步执行 EOF 循环
点击“执行一步”，观察每次 READFILE 读到什么、EOF 什么时候变 TRUE。

20.4 文件的四个高频扣分点

COMMON MISTAKES
1漏 CLOSEFILE——几乎每次考试都有这 1 分。
2模式用错：READ 模式下 WRITEFILE；想追加却用 WRITE（旧数据被清空）。
3EOF 循环漏 NOT，或把 READFILE 写在循环外。
4WRITE 和 READ 的顺序不对应：写入写了 3 个值，读取也必须按同顺序读 3 个值。

20.5 真题小练：追加一条记录再全部显示

EXERCISE
题目 文件 Marks.txt 已存在。输入一位新学生的姓名与分数追加到文件末尾，然后读出全部记录并输出。 
DECLARE Name : STRING
DECLARE Mark : INTEGER
DECLARE ThisName : STRING
DECLARE ThisMark : INTEGER

// 第一步：追加（APPEND，不清空旧内容）
OUTPUT "Enter name"
INPUT Name
OUTPUT "Enter mark"
INPUT Mark
OPENFILE "Marks.txt" FOR APPEND
WRITEFILE "Marks.txt", Name, Mark
CLOSEFILE "Marks.txt"

// 第二步：全部读出
OPENFILE "Marks.txt" FOR READ
WHILE NOT EOF("Marks.txt") DO
  READFILE "Marks.txt", ThisName
  READFILE "Marks.txt", ThisMark
  OUTPUT ThisName, " ", ThisMark
ENDWHILE
CLOSEFILE "Marks.txt"
两段之间必须关了再开 追加和读取是两种不同的使用方式，所以要先 CLOSEFILE 再用 READ 重新 OPENFILE。 一次 OPEN 只对应一种模式。

第 21 章 · 数据校验与三类错误

用户输入永远不可信。校验（validation）就是程序在接收数据后先检查“合理不合理”，不合理就要求重输。 这一章的固定句式只有一个：校验循环。另外，Paper 2 每年都会考三类错误的名词辨析， 一张表就能拿满。

21.1 校验循环：一个模板打天下

VALIDATION LOOP

不管校验什么条件，结构永远是“输入 → 检查 → 不合法就提示重输”。用 REPEAT 写最顺：

DECLARE Age : INTEGER

REPEAT
  OUTPUT "Enter your age (1-120)"
  INPUT Age
  IF Age < 1 OR Age > 120 THEN
    OUTPUT "Invalid age, please try again"
  ENDIF
UNTIL Age >= 1 AND Age <= 120
  • UNTIL 后面写的是停止条件（“合法了就停”），方向别写成“不合法就停”。
  • 用 WHILE 写也一样：WHILE Age < 1 OR Age > 120 DO … ENDWHILE，此时条件是“继续循环的条件”。
  • REPEAT 至少执行一次，天然适合“必须先拿到一个输入”的场景。
两处判断互为镜像 IF 里的条件是“非法时提示”，UNTIL 里的条件是“合法时退出”。把同一组比较运算符 原样抄过去再加个 NOT 的思路最稳：UNTIL NOT (Age < 1 OR Age > 120) 也算正确。

21.2 四种常见校验

CHECK TYPES
校验检查内容判断写法示例
范围检查 range数值在上下限之间Age >= 1 AND Age <= 120
长度检查 length字符串字符数符合要求LENGTH(Password) >= 8
类型检查 type输入的是不是数字 / 日期格式逐字符判断是否 0–9（循环 + 比较）
存在检查 presence / lookup输入的值在数据里查得到遍历数组逐个比较，配合 Found 标志

存在检查是最常综合考的一种，标准骨架是“标志变量 + 循环比较”：

DECLARE Names : ARRAY[1:50] OF STRING
DECLARE i : INTEGER
DECLARE Probe : STRING
DECLARE Found : BOOLEAN

OUTPUT "Enter name to search"
INPUT Probe
Found ← FALSE
FOR i ← 1 TO 50
  IF Names[i] = Probe THEN Found ← TRUE
NEXT i
IF Found = FALSE THEN OUTPUT "Name not found"

21.3 校验 ≠ 验证

VALIDATION VS VERIFICATION
概念含义例子
校验 validation程序自动检查输入是否合理、是否符合规则年龄必须在 1–120；密码至少 8 位
验证 verification检查输入是否与原意一致（有没有输错）密码输入两遍互相核对；屏幕上回显确认
一句话记住 校验答“这个值像不像话”，验证答“这个值是不是你想输的”。 合法但不正确的值（把 18 输成 81）校验查不出来——这就是为什么还需要验证。

21.4 三类错误：每年必考的名词题

THREE ERROR TYPES
错误类型含义例子
语法错误 syntax error违反伪代码/语言的书写规则漏 ENDIF；FOR 拼成 FORR；字符串漏引号
逻辑错误 logic error语法正确但算法想错了，程序能跑、结果不对找最大值用了 <；累加器清零放错位置
运行时错误 runtime error执行到某一步才发生，程序中断除数为 0；数组下标越界；打开不存在的文件
辨析 1 Total ← Total + 1 写成 Total ← Total + 2： 程序照样运行——这是逻辑错误，不是语法错误。
辨析 2 数组声明 ARRAY[1:5] 却访问 List[8]： 语法完全正确，一执行才中断——这是运行时错误。

21.5 真题小练：日期校验

EXERCISE
题目 输入月份 Month（1–12）与日期 Day（1–31）。月份不合法或日期不合法都要提示重输； 4、6、9、11 月的天数上限是 30。 
DECLARE Month, Day : INTEGER
DECLARE Valid : BOOLEAN

REPEAT
  OUTPUT "Enter month (1-12)"
  INPUT Month
  IF Month < 1 OR Month > 12 THEN
    OUTPUT "Invalid month"
  ENDIF
UNTIL Month >= 1 AND Month <= 12

REPEAT
  OUTPUT "Enter day"
  INPUT Day
  IF (Month = 4 OR Month = 6 OR Month = 9 OR Month = 11) THEN
    Valid ← (Day >= 1 AND Day <= 30)
  ELSE
    Valid ← (Day >= 1 AND Day <= 31)
  ENDIF
  IF Valid = FALSE THEN OUTPUT "Invalid day for this month"
UNTIL Valid = TRUE
阅卷提示 校验题的得分点：范围判断的正确使用、提示输出、循环条件与 IF 条件方向一致。 题目说“提示重输”就必须真的有 OUTPUT，只判断不提示会扣分。
下一步 校验写好了，怎么证明它没写错？用测试数据去打它——正常、边界、无效各来几条，见第 22 章。

第 22 章 · 测试数据与测试计划

程序能跑，不等于它是对的。怎么证明它是对的？用挑过的数据去打它。 这一章解决三件事：测试数据分几类、每一类怎么选、测试表怎么填。 考纲把它单独列成一个小节（test data），Paper 2 里通常是一道 3–4 分的送分题—— 但每年都有大量学生把“边界数据”写成“范围内的任意值”。

22.1 四类测试数据

FOUR CATEGORIES

以“输入年龄，合法范围 11–18 的整数”为例，四类数据的分工一目了然：

类型定义例子期望结果
正常数据
normal		范围内的普通值，不靠边界15、14接受，正常往下执行
边界数据
boundary		正好等于范围的上限或下限11、18接受（它们是合法值）
无效数据
invalid / erroneous		格式不对、类型不对，或明显超出范围“abc”、10、19、-3拒绝，提示重输
极端数据
extreme		接近数据类型上限或下限的值（与业务范围无关），用来试探程序会不会崩0、999999、空字符串、超长字符串拒绝或安全处理，不能崩溃
边界数据为什么必须单独列 大多数范围判断的错误都发生在边界上：>= 11 写成 > 11，用 15 测一百次也发现不了， 用 11 测一次就露馅。所以“正常数据 + 边界数据 + 无效数据”三件套，是任何输入题的标配。

22.2 一次真实的翻车：边界写错

OFF-BY-ONE

下面这段校验把下限写成了“大于 11”，11 岁的人会被拒之门外：

REPEAT
  OUTPUT "Enter age (11-18)"
  INPUT Age
UNTIL Age > 11 AND Age < 18      // 错误：11 和 18 都被拒绝了
测试值类型正确程序这段程序
15正常接受接受（测不出问题）
11边界接受拒绝 ← 错误暴露
18边界接受拒绝 ← 错误暴露
19无效拒绝拒绝（恰好正确）
结论 只用“正常数据”测试，等于没测。测试的价值不在于证明程序对，而在于尽快让它错—— 所以每类数据至少一条，边界必须覆盖上下限。

22.3 测试计划表怎么写

TEST PLAN

题目说 “complete the test plan” 时，表格一般已经给好表头，你只需要补行。每一行必须写清“输入什么、属于哪类、期望输出什么”：

测试号测试数据数据类型期望结果
115正常接受，继续询问下一项
211边界（下限）接受
318边界（上限）接受
410无效（低于下限）输出错误提示，要求重新输入
519无效（高于上限）输出错误提示，要求重新输入

22.4 四步选出合格的一组数据

HOW TO CHOOSE

① 找规则

从题干里抄出合法范围、长度、格式。规则不明，测试无从谈起。

② 取中间

正常数据选范围中部的普通值，如 11–18 取 15。

③ 卡边界

上下限各来一条：11 和 18。这是最能抓错的两条。

④ 撞错误

至少一条类型错的（字母、空值、符号），一条超范围的。

常见扣分 题目要求“三种类型各一条”，却写了 12、15、16 三条正常数据——类型不齐，最多拿一半分。 另外，写 “10” 时别标成“边界”，它是无效数据；边界只指 11 和 18 这两个合法端点。

23.2 三条规矩

THREE RULES

① 一行 = 一次迭代

循环体每执行一次写一行，不是每条语句一行。循环前的初始化和循环后的输出各占单独一行。

② 只写当前值

格子里写 30，不写 “12 + 18”，也不写 “30（原 12）”。卷面只认最终值，算式会被当成分数线划掉。

③ 条件写 TRUE / FALSE

条件列只填 TRUE 或 FALSE（部分教材用 Yes / No）。写 “12 大于 10 所以成立” 会占满格子还得不到分。

列该开几个 题目给好的表头照抄即可。要自己开表时：循环变量 + 每次取到的元素 + 每个会变的变量 + 每个影响分支的条件。 不要给常量开列（它永远不变，开了也没信息）；也不要漏掉标志变量——它恰恰是最容易错的一列。

第 24 章 · 流程图

流程图用图形表示算法的步骤与顺序。它和伪代码是同一件事的两种表达： 图看结构，代码看细节。考试形式通常是“补全流程图”或“把图翻译成伪代码”， 所以这一章真正要练的是双向转换。

24.1 五种符号

SYMBOLS
符号名称用途

Process
处理		 赋值、计算等动作，直角矩形

24.4 图 ↔ 代码 三步法

CONVERSION METHOD

第 1 步：找骨架

先数圆角符（1 个 START，1 个 STOP），再找所有菱形。有几个菱形，就有几个 IF 或循环条件。

第 2 步：定结构

把每个矩形的赋值、每个平行四边形的 INPUT/OUTPUT 照抄进去，最后补上声明与收尾关键字。

25.1 题目要求拆解

REQUIREMENTS

场景：一家木地板公司最多记录 100 位客户。每种木地板有单价，客户报房间长宽（米），系统算出面积与总价。

编号要求考点
R1输入客户姓名、房间长、宽，长宽需在 1–5 米之间并做校验；姓名不能含 *，含 * 表示结束REPEAT + WHILE 双层校验

R3输出完整的客户报价信息，包括各字段的含义说明，循环直到输入 *OUTPUT + 循环控制
给定数据 三种类型与单价：Laminate 23.59、Wood 28.99、Oak 54.99（每平方米）。 题目已经给了两个数组的初始化代码，照抄进答案即可拿分，但不要改结构。

25.2 满分伪代码

FULL SOLUTION
// ================= 1. 声明与初始化 =================
DECLARE WoodType : ARRAY[1:3] OF STRING
DECLARE Price : ARRAY[1:3] OF REAL
DECLARE Quotations : ARRAY[1:100, 1:6] OF STRING

DECLARE CustomerName : STRING
DECLARE RoomLength : REAL
DECLARE RoomWidth : REAL
DECLARE RoomArea : REAL
DECLARE WoodChoice : INTEGER
DECLARE WoodCost : REAL
DECLARE CurrentCustomer : INTEGER
DECLARE Valid : BOOLEAN

WoodType[1] ← "Laminate"
WoodType[2] ← "Wood"
WoodType[3] ← "Oak"
Price[1] ← 23.59
Price[2] ← 28.99
Price[3] ← 54.99

CurrentCustomer ← 1

// ================= 2. 主循环：直到输入 * 或满 100 人 =================
REPEAT
   OUTPUT "Enter customer name (enter * to stop): "
   INPUT CustomerName

   IF CustomerName <> "*" THEN

      // ---- 2.1 长度校验：1 到 5 米 ----
      Valid ← FALSE
      WHILE Valid = FALSE
         OUTPUT "Enter room length in metres (1 to 5): "
         INPUT RoomLength
         IF RoomLength >= 1 AND RoomLength <= 5 THEN
            Valid ← TRUE
         ELSE
            OUTPUT "Invalid length, please try again"
         ENDIF
      ENDWHILE

      // ---- 2.2 宽度校验：同样 1 到 5 米 ----
      Valid ← FALSE
      WHILE Valid = FALSE
         OUTPUT "Enter room width in metres (1 to 5): "
         INPUT RoomWidth
         IF RoomWidth >= 1 AND RoomWidth <= 5 THEN
            Valid ← TRUE
         ELSE
            OUTPUT "Invalid width, please try again"
         ENDIF
      ENDWHILE

      Valid ← FALSE

         INPUT WoodChoice
         IF WoodChoice >= 1 AND WoodChoice <= 3 THEN
            Valid ← TRUE
         ELSE
            OUTPUT "Your input is out of range, please try again"
         ENDIF

      RoomArea ← RoomLength * RoomWidth
      WoodCost ← RoomArea * Price[WoodChoice]

      Quotations[CurrentCustomer, 1] ← CustomerName
      Quotations[CurrentCustomer, 2] ← WoodType[WoodChoice]

      Quotations[CurrentCustomer, 4] ← RoomWidth

      OUTPUT "Room area: ", Quotations[CurrentCustomer, 5]

25.3 关键六句，为什么必须这样写

SIX KEY LINES
代码理由
CurrentCustomer ← 1下标必须从 1 开始准备（题目声明是 1:100），且要在循环外面初始化一次
IF CustomerName <> “*” THEN … ENDIF输入 * 是“退出信号”，不该被当成一位客户去算面积，所以处理逻辑要包在判断里
Valid ← FALSE → WHILE Valid = FALSE校验的经典写法：只要不合法就一直问。用标志变量比自己写 WHILE NOT(...) 更清晰
Price[WoodChoice]用户输入的是编号，单价要按编号查表拿，不能写三个 IF 分支去硬编码
Quotations[CurrentCustomer, 3] ← RoomLength二维数组先写行（第几位客户）再写列（第几个字段）；这是“一条记录”的写法
CurrentCustomer ← CurrentCustomer + 1在 IF 内部自增：如果输入的是 *，不该占用一个客户编号
这题的隐藏陷阱：类型混装 一列里既有姓名（字符串）又有面积（实数），严格来说一个数组不能混类型。 考试答案允许把 Quotations 声明成 STRING，把数字当字符存；如果你要更严谨， 应改成平行数组：QName[1:100] OF STRING、QArea[1:100] OF REAL 等。 两种写法都能得分，但要自洽——不要一半用二维数组一半用平行数组。

25.5 进阶：姓名里逐个字符查 *

CHAR SCAN

如果题目要求“姓名中任何位置出现 * 都算无效”，仅用 CustomerName <> “*” 不够（那只能判断“整个名字就是一个星号”）。 这时要把字符串拆成字符逐个比较，正好用上 LENGTH + SUBSTRING + 循环：

DECLARE HasStar : BOOLEAN
DECLARE i : INTEGER

HasStar ← FALSE
FOR i ← 1 TO LENGTH(CustomerName)
   IF SUBSTRING(CustomerName, i, 1) = "*" THEN
      HasStar ← TRUE
   ENDIF
NEXT i

IF HasStar = TRUE THEN
   OUTPUT "Name contains *, ending input"
ENDIF
这段代码的价值 它同时展示了三件事：字符串下标从 1 开始、用 LENGTH 控制循环次数、用标志变量记录“是否发生过”。 这三件事在 Paper 2 里几乎每次都会以不同组合出现。
